### 1. Роли и функционал приложения

В разрабатываемом приложении предусмотрены две роли пользователей: **Слушатель** и **Администратор**.

#### 1.1. Слушатель
Пользователь, использующий клиентскую часть приложения для поиска и прослушивания контента.

*   **Поиск и навигация:**
    *   Поиск подкастов по ключевым словам (название) и фильтрация по категориям,
    *   Получение от сервера списка подкастов в формате JSON, содержащего идентификаторы (ID) и метаданные.
*   **Выбор контента:**
    *   Выбор конкретного подкаста для воспроизведения на основе полученного списка.
*   **Воспроизведение (стриминг):**
    *   Потоковое прослушивание аудиоконтента.
    *   **Алгоритм воспроизведения:**
        *   Начало воспроизведения с 0-й секунды (или выбранной метки),
        *   Автоматический расчет номера текущего аудио-фрагмента относительно времени воспроизведения,
        *   Проверка локального кеша на наличие нужного фрагмента,
        *   Отправка запроса на сервер (*«Дай мне N фрагмент подкаста {ID}»*), если фрагмент отсутствует в кеше,
        *   Фоновая предзагрузка следующих сегментов для обеспечения непрерывного воспроизведения.

#### 1.2. Администратор
Пользователь, ответственный за управление контентом. Взаимодействие с издателями подкастов происходит через сторонние каналы связи; администратор выступает оператором ввода данных в систему.

*   **Публикация контента:**
    *   Получение исходного аудиофайла и метаданных от издателя,
    *   Ввод метаданных (название, категория, описание) и отправка их на сервер,
    *   Загрузка аудиофайла на сервер.
*   **Обработка данных (системная функция, инициируемая Администратором):**
    *   Прием файла сервером в потоковом режиме (без полной загрузки в ОЗУ),
    *   Автоматическая нарезка исходного файла на сегменты длительностью 1 минута,
    *   Сохранение сегментов в файловую систему по шаблону: `/podcasts/{ID}/{N}.mp3`,
    *   Создание записи в БД (MySQL) с присвоением уникального ID.
*   **Удаление контента:**
    *   Инициирование удаления подкаста по его ID,
    *   Синхронное удаление записи из базы данных и соответствующей директории с файлами из файловой системы.

### 2. Ограничения на ввод информации пользователем

Данный раздел описывает правила валидации и технические ограничения, накладываемые на данные, вводимые пользователями.

#### 2.1. Для Слушателя
*   **Поисковые запросы:**
    *   Тип данных: строка,
    *   Максимальная длина запроса: ограничена (например, до 255 символов) для предотвращения переполнения буфера,
    *   Санитизация: автоматическое экранирование специальных символов для защиты от SQL-инъекций при запросах к БД.
*   **Запросы фрагментов:**
    *   Идентификатор подкаста (ID): должен быть существующим целым числом,
    *   Номер фрагмента (N): должен быть неотрицательным целым числом, не превышающим общее количество сегментов конкретного подкаста.

#### 2.2. Для Администратора
*   **Метаданные подкаста:**
    *   Название: обязательное поле, текстовый формат, не должно быть пустым,
    *   Категория: выбор из предопределенного списка или текстовое поле с ограничением по длине.
*   **Загрузка файлов:**
    *   **Формат файла:** строгое ограничение на формат аудио (например, только `.mp3` или `.wav`),
    *   **Целостность:** файл должен быть корректным аудио-потоком (валидация на уровне заголовков файла при начале загрузки),
    *   **Обработка памяти:** поскольку загрузка реализована через поток, ограничение на размер файла определяется только свободным местом на диске сервера, а не объемом оперативной памяти. Однако может быть установлен тайм-аут на длительность загрузки (execution time limit) со стороны сервера.
